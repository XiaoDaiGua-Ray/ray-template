# Hooks and utilities review — November 2026

## Scope and acceptance

Reviewed every implementation reachable from `apps/admin/src/hooks`, `apps/admin/src/utils`, `packages/composables/src`, and `packages/utils/src`. Compatibility entry points were followed to their owners instead of counted as separate implementations. The source inventory contains 141 named implementations in 44 files, plus the layout-owned `positionSelectedMenuItem` reached through its historical utility export. Inline event callbacks and returned object methods were also inspected. Component-local hooks and utilities are covered by the [component review](2026-11-components.md).

Acceptance covers observable correctness, reactive state ownership, resource cleanup, bounded allocations, configuration behavior, and accurate function contracts. It does not mean every function needs a rewrite or that a CPU benchmark proves browser responsiveness.

## Findings and changes

| Finding                                                                                                           | Change                                                                                                                                | Evidence                                                                                                                                                                        |
| ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default pagination candidates shared one mutable array across hook instances.                                     | Give each instance its own default `pageSizes` array. Caller-provided arrays retain caller ownership.                                 | Two simultaneous instances and a later instance retain independent defaults after one is mutated.                                                                               |
| Pagination reset consulted startup candidates after the exposed configuration had changed.                        | Read `pagination.value.pageSizes` at reset time, including object options and the empty fallback.                                     | Replacement with a 25-row option and then an empty array resets to 25 and 10 respectively.                                                                                      |
| Shared storage could overwrite valid JSON with the non-JSON result of `JSON.stringify(undefined)`.                | Serialize first and skip writes when serialization returns `undefined` or throws. Keep the existing backend, prefix, and JSON format. | `undefined`, functions, symbols, cycles, and BigInt preserve saved content; JSON `null` still writes normally.                                                                  |
| A fullscreen hook could reacquire an element after its effect scope was destroyed, leaving no live cleanup owner. | Mark the instance disposed before restoring it and ignore subsequent entry attempts.                                                  | Disposal restores style priorities and previous attributes, blocks the old instance, and lets a new instance acquire the element.                                               |
| Random identifiers invoked Web Crypto separately for every character.                                             | Fill a bounded buffer of at most 128 samples and retain rejection sampling.                                                           | Rejected samples, multiple batches, radix boundaries, and a 70,000-character identifier are covered. No random-source weakening or modulo bias was introduced.                  |
| PNG Base64 conversion created one array entry per byte.                                                           | Prefer native `Uint8Array.toBase64`; use bounded 32 KiB string chunks when unavailable.                                               | Empty data, all byte values, large buffers, chunk boundaries, and forced fallback produce identical Base64.                                                                     |
| Every permission requirement searched the entire permission array.                                                | Cache a computed Set per hook instance and use direct membership checks; rebuild on reactive permission changes.                      | Single/all/any checks, empty-list semantics, in-place revocation, and replacing session permissions are covered.                                                                |
| The screenshot renderer was statically imported even when never used.                                             | Dynamically import `html-to-image` within the existing asynchronous `create` method after validating the target.                      | Configured/overridden formats, callback ordering, renderer errors, and missing/throwing targets remain covered. Browser/build acceptance is recorded by the integrating review. |

The Base64 fast path follows the [native typed-array API](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Uint8Array/toBase64); feature detection preserves older browsers. No dependency, package export, persistence key, or ciphertext format was changed.

The integrating review additionally optimized `useTheme` by capturing its reactive getter, actions and translator once per factory; repeated reads no longer rebuild all settings computed references. A same-instance theme/language change regression confirms the result is not a cached snapshot.

The later [routing review](2026-11-routing.md) supersedes the original root/tab behavior and documents the final neutral-workspace contract.

## Comment audit

Public factories, exported utilities, and returned action methods now have adjacent contract comments where this module owns the declaration. Comments follow the initial blank line, actual parameter names/order, standalone `@description`, and `@param` → `@description` → `@returns` → `@throws` order. They do not add `@returns` to void actions. Public overloads carry one shared contract, while small private normalizers and platform-typed callback bodies use local implementation notes rather than repetitive JSDoc.

The audit also corrected specificity: the screenshot promise includes dependency loading, fullscreen callbacks do not mean animation completion, `useSpinning` delegates restoration to the Store, color parsing covers comma-separated rgb/hsl, and fixed-point arithmetic is bounded by Number's safe-integer range.

## Verification and remaining boundaries

- Initial regression run: `pnpm test:run __test__/hooks __test__/cache __test__/basic __test__/precision __test__/utils-contracts __test__/vue __test__/element __test__/dom` passed 49 files / 218 tests before the final native-Base64 fallback case was added.
- Final affected-case rerun: `pnpm test:run __test__/basic/arrayBufferToBase64Image.spec.ts __test__/cache/shared-storage.spec.ts __test__/hooks/useAccess.spec.ts` passed 3 files / 8 tests. `vue-tsc -p tsconfig.packages.json --noEmit` and `vue-tsc -p tsconfig.test.json --noEmit` passed. ESLint with zero warnings and Prettier checks passed for all owned changed files.
- The integrating agent records final type, lint, formatting, build and browser outcomes for the combined change. Screenshot creation on `/web-hooks` is the affected lazy-load interaction; other hooks keep their visible behavior.
- Browser rendering, image/font cross-origin restrictions, native print dialogs, and physical print output are not established by Happy DOM tests. No physical printing is required for the internal changes in this review.
- No universal speedup, mobile-device latency, memory ceiling, or cross-browser benchmark is claimed. The proven changes remove per-character crypto calls, per-byte fallback array entries, repeated permission scans, and eager screenshot imports while retaining the documented API behavior.
- Large synchronous Base64 requests still allocate the output string. If measured payload sizes block interaction, add an explicitly asynchronous/worker API at that consumer boundary rather than silently changing this synchronous API.
- Native Storage calls remain synchronous; demo memory storage is intended for the small isolated documentation dataset. Existing native DOM class changes do not make `hasClass` reactive. Legacy AES remains a compatibility format, and fixed-point functions remain Number-backed. Revisit those choices only with a concrete workload or migration requirement.

## Guidance applied

The Modern Web Guidance `performance` guide recommends “**DO use dynamic imports**”. The screenshot implementation follows that recommendation while leaving the synchronous print API intact. The generic performance guidance does not justify changing date, storage, or compatibility contracts to newer APIs without an observed need.
