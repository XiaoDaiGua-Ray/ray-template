# UI refinement review — November 2026

## Scope and acceptance

Review the four existing interface styles, initial startup feedback, and the content loader used by `useSpinning`. Preserve saved preferences, custom primary colors, language, route/loading ownership, and the existing Naive UI configuration contract. Refinement means consistent shapes, clear hierarchy, readable secondary content, restrained elevation, and feedback that cannot be mistaken for a control.

## Chart style packs

All eight JSON packs were reviewed field by field: categorical colors, canvas, title/subtitle, legend, tooltip, pointer/crosshair labels, category/value/time/log axes, grids, line widths/area opacity, bar radii, and pie separators. Canvas colors match their owning page card surfaces. Explicit business options remain authoritative, following the [ECharts style contract](https://echarts.apache.org/handbook/en/concepts/style/).

The existing Modern blue/teal/violet sequence and Material purple/tonal sequence were already coherent. Naive keeps its green-led palette. Plain keeps low-saturation categorical hues so separate series remain distinguishable without turning the style into a colorful dashboard. No series palette was changed merely for novelty.

Ratios use sRGB relative luminance after compositing alpha against the actual canvas. Tooltip text is at least 7.74:1 across these packs. Naive/Plain previously used divider colors for interactive pointers; those four packs now distinguish the pointer from the decorative grid. The minimum 3:1 target for meaningful graphical marks follows [W3C non-text contrast guidance](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html). The measurements are against the chart canvas, not a claim that every overlapping area, adjacent pie slice, or custom chart satisfies accessibility requirements.

The loading-style audit also reproduced `transparent` becoming `rgba(0,0,0,0.9)` when alpha was replaced. `loadingOptions` now parses once and falls back to the mode's surface when the custom theme has no usable background. It retains selected theme colors and caller overrides without modifying the theme object.

## Verification

- Browser follow-up found that an entry dependency could fail before `main.ts` installed its async error handler. An inline capture listener now sends module resource errors and script `ErrorEvent`s to the existing failure/retry UI, ignores image errors, and becomes inert once the splash is removed. It is removed on the next post-mount error and adds no timeout or module dependency. This follows the separate [script-element fetch-error](https://html.spec.whatwg.org/multipage/scripting.html#execute-the-script-element) and [module evaluation-error](https://html.spec.whatwg.org/multipage/webappapis.html#run-a-module-script) paths. Vite regenerates bundled module tags, so an `onerror` attribute on the source tag would not cover production output reliably.
- `boot-feedback.spec.ts` passed 4 focused cases for captured module resource failure, script evaluation failure, unrelated image errors, and post-mount cleanup.
- `chart-themes.spec.ts` adds 30 deterministic checks for all eight theme registrations/surfaces, text and data/pointer contrast, loading masks, transparent/invalid backgrounds, and caller overrides. It passed together with the existing chart and startup-feedback regressions: 3 files, 39 tests.
- Focused Vitest run passed: `content-loading.spec.tsx`, `global-provider.spec.ts`, and `preferences.spec.ts` — 3 files, 13 tests. New cases cover delayed feedback, short-operation cancellation, unmount cleanup, native progress labeling, and immediate remount feedback.
- ESLint passed for changed TypeScript/TSX files. Prettier passed for the UI implementation and tests.
- The lead agent visually accepted dashboard consumers in all four styles and both modes, and all eight actual chart palettes/tooltips. ECharts retained the same instance through the switches. The checked flows had no console errors.
- At 390px in English/dark mode, the content loader retained its unboxed label, native progress, 6s reduced-motion sweep, and no horizontal overflow. Forced-colors track/fill borders remained visible.
- A local proxy fixture generated from the actual served startup HTML verified Material dark/English startup at 390px, reduced motion, genuine module-resource failure, and a missing named export in a module dependency. Both failures displayed the alert and Reload action; Reload started a new document. These are controlled failure probes, separate from the real application-flow checks and the final production build/preview.
- Screenshots are stored under `.harness-local/quality-review/screenshots/`. The lead agent owns the final combined build and browser evidence record.
- No device-matrix or assistive-technology certification is claimed. The loader retains native semantics, but real screen-reader testing is separate from DOM assertions.

## Guidance applied

- `spinner`: “Without a `value` attribute, it is implicitly indeterminate.” The loading state uses native progress semantics without inventing a completion percentage; a decorative line represents activity.
- `motion`: “Prefer to animate `opacity` and `transform`”. Loading animation uses compositor-friendly transforms; startup entrance uses only opacity and transform.
- `motion`: “DO NOT globally apply `animation-duration: 0.01ms;`”. Reduced motion is handled at the affected animations rather than accelerating infinite effects.
- `accessibility`: “Don't use live regions for interstitial states”. Routine content loading exposes progress semantics without introducing repeated live announcements.
- `color`: “Maintain 4.5:1 for normal text” and “a minimum contrast ratio of 3:1”. Chart palette checks composite alpha before measuring; interactive pointers use a stronger color than decorative dividers.
