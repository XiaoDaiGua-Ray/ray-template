# Fullstack PC acceptance plan

Scope: the optional backend, its Admin integration, the frontend-only Mock contract, and independent source setup. Acceptance uses one desktop Chrome session and disposable PostgreSQL, Redis, and Compose resources.

| Baseline finding                                                                                                                                                                                                                                       | Implementation and acceptance                                                                                                                                                                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A clean install and external setup start the existing Admin and Nest app. Anonymous `/admin/route-config` returns nine root entries; only the editor view is protected. Local browser route preferences can bypass the server's runtime configuration. | Authenticate the runtime snapshot and prune by live grants, inherited roles, view permissions, and demo policy. Drop empty groups and unusable redirects. Preserve the separate authorized editor snapshot. Inject only the current account's routes. Denied injected paths resolve as absent (404); reserved protected pages and API permissions still return 403. |
| Baseline login returns an opaque token to local storage. There is no self-service profile or password endpoint; the avatar entry is a placeholder. Account credentials require CLI access.                                                             | Sign and verify bounded JWT sessions while keeping the PostgreSQL revocation boundary. Use an HttpOnly cookie for the bundled same-origin Admin and preserve explicit Bearer access for API clients and Mock. Add self profile, current-password verification, all-session revocation, and a separately authorized administrator credential action.                 |
| Setup is repeatable by username, so a renamed bootstrap account can cause a second privileged account to be created. Readiness only checks connections. Container startup requires a separate local setup command.                                     | Bootstrap once using the existing audit marker; preserve accounts, grants and route configuration across setup. Report uninitialized databases as unready. Provide a single Compose launch command and a runbook with external service, upgrade, secret, and troubleshooting instructions.                                                                          |
| The local screen lock accepts a browser-stored password while the real API session remains active.                                                                                                                                                     | Keep the local privacy screen for Mock. In real mode, locking revokes the current session and keeps the current address for reauthentication.                                                                                                                                                                                                                       |

Plan review: The menu is not an authorization boundary. Protected data stays behind live endpoint checks, including writes inside transactions. The router must distinguish an intentionally empty snapshot from failed loading, and neither should select the packaged route list in server mode. The editor must still receive routes hidden by role or demo policy. Cookie transport requires a same-origin browser request and must not return the token in JSON. Credential changes must not permit self-promotion, target substitution, or use of the previous session. Upgrades may require a new login and signing secret, but must preserve database data and the frontend-only distribution.

Verification gates: full Harness; HTTP integration with real PostgreSQL and Redis (including denied requests and session races); desktop browser against real API with admin and limited accounts; extracted fullstack and frontend archives; actual Compose build, fresh start and smoke checks.
