The application's `@/components` and some hook/directive paths retain compatibility exports. Follow exports into the owning shared package before fixing common behavior. Inject host-specific services instead of referencing application aliases from shared packages. Add both Chinese and English for new interface copy.

Before adding a component, check existing capabilities using the [Harness reuse conventions](../README.md#engineering-conventions). For full-height content and independent scrolling, start with [TablePro height styles](../../packages/ui/src/RTablePro/src/index.scss), [layout height variables](../../packages/admin-shell/src/layout-css-vars.ts), and the [user management page](../../apps/admin/src/views/user-management/index.tsx). `RTablePro autoHeight` uses `--r-table-height` to fill its host. Naive UI's `NCard contentScrollable` and `NScrollbar` handle scrolling; the parent uses Flex/Grid and `min-block-size: 0` to provide a definite height that can shrink.

Targeted verification: for small fixes, run the relevant [component](../../__test__/components), [hook](../../__test__/hooks), or [cross-package consumer](../../__test__/workspace/consumer.spec.tsx) test file. Use `pnpm harness verify ui` for scope-level regression coverage; it runs Vitest without launching a browser. For visible effects or interactions, choose pages and dimensions using [Harness browser verification](../README.md#browser-verification).
